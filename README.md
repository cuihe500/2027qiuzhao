# 2027届秋招信息汇总

Vue 3 + Vite 前端，Node.js + SQLite 后端。支持公司与岗位筛选、投递进度记录、备份恢复和多端同步。

## 快速开始

需要 **Node.js 24 或更高版本**（使用内置 `node:sqlite`，无需另装数据库）。

```bash
npm install
npm run dev
```

打开终端显示的 Vite 地址（默认 `http://localhost:5173`）。开发命令同时启动 Vue 和 API 服务；Vite 将 `/api`、`/data.json` 代理到后端，浏览器只访问一个站点。

在登录页面使用用户名 **`XiaoLv`**、密码 **`XiaoLvBaoBei`**。登录后即可查看公司表格、修改投递进度，所有设备使用同一个账号。

可复制 `.env.example` 为 `.env` 修改配置：

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | 后端监听地址 |
| `PORT` | `3001` | 后端端口，也是 Vite 代理目标端口 |
| `DATABASE_PATH` | `storage/qiuzhao.sqlite` | SQLite 文件位置 |
| `DATA_PATH` | `data.json` | 公司信息文件位置 |

相对路径按启动命令所在目录解析，请从项目根目录运行命令。`.env` 和数据库文件已加入 `.gitignore`。

## 登录与多端同步

1. 在任意设备打开**同一个服务地址**，使用 `XiaoLv` / `XiaoLvBaoBei` 登录。
2. 登录后自动读取该账号在 SQLite 中保存的投递进度，无需额外创建或连接同步凭证。
3. 修改投递状态后自动同步；每 15 秒、重新联网或窗口重新获得焦点时读取其他设备的变更，也可在「进度同步」中点击「立即同步」。

这是单用户应用：所有设备共用一个账号和一份进度，不提供注册或多账号管理。登录状态保存在有效期为 30 天的 HttpOnly、SameSite=Lax Cookie 中；刷新页面或重启服务器后仍可继续使用。点击「退出登录」或登录过期后，需要重新登录才能进入主页面。

- 已登录且打开的页面断网时仍可修改进度，待发送变更保存在本地，重新联网后重试。重新打开页面需要连接服务器验证登录并读取公司数据。
- 每家公司独立检测版本冲突。同一家公司被多端同时修改时，可选择保留此设备或服务器版本；清空记录也会同步，旧设备不能静默恢复已清空的记录。
- 同一浏览器的多个标签页共享缓存，不同公司的离线修改分别持久化；多个标签页同时修改同一家公司时，以最后写入本地缓存的记录为准。
- 首次登录且服务器从未保存过进度时，会自动迁移此设备的旧记录；服务器已有历史记录时，通过「合并此设备本地进度」明确导入，同名公司使用本地记录。
- 退出登录不删除服务器进度或本地待发送修改，重新登录后继续同步。
- 旧版 `qiuzhao2027_progress_v2` / `v1` 本地记录自动迁移。更换域名、协议或端口后，浏览器存储不共享，请先在旧站「备份进度」，再在新站「恢复进度」。

升级已有 SQLite 数据库时，只有一份旧同步数据会直接沿用；存在多份时默认沿用进度记录最多的一份，其余数据仍保留在数据库中。

只有投递状态、各阶段日期及结束阶段会发送到同步后端。简历、面试会话、报告与 AI API Key 不参与同步，仍保留在当前浏览器；使用用户配置的大模型服务时，面试助手按原有功能向该服务发送必要内容。

## 动态公司数据

公司表格由 Vue 响应式渲染，**每次打开页面均请求最新 `/data.json`**；「检查更新」可在不刷新页面的情况下重新读取。

后端每次请求都读取根目录的数据文件，前后端均禁用该请求的缓存。表格、分类、公司数量和数据日期一起更新，即使 `rev` 未变化也会应用新的文件内容；公司信息更新不会覆盖个人投递进度。读取失败时明确提示，可重试；手动刷新失败则保留本次页面已成功读取的数据。

保留的数据结构：

```json
{
  "rev": "20260926-a",
  "updated": "2026-09-26",
  "count": 1,
  "data": [
    {
      "company": "示例公司",
      "date": "2026-09-26",
      "roles": "产品经理、研发",
      "portal": "https://example.com/jobs",
      "note": "面向2027届",
      "source": "官方招聘网站",
      "ent": "民企",
      "cohort": "2027届"
    }
  ],
  "cats": { "示例公司": "互联网/软件" }
}
```

公司名称作为进度记录的标识，需保持唯一和稳定。表格分页支持每页 50 / 100 / 200 家；CSV 导出当前筛选结果，JSON 备份包含全部个人进度。

[上游同步工作流](.github/workflows/sync-data.yml) 保留：每 5 分钟检查上游 [xinyangli-326/2027qiuzhao](https://github.com/xinyangli-326/2027qiuzhao) 的 `data.json`，有变化且结构通过校验后提交到 `main`。GitHub 调度可能延迟，也可在 Actions 手动运行。

工作流只更新仓库文件。部署服务器仍需通过拉取仓库或部署流程取得新文件；文件更新到服务器后，无需重建前端或重启服务即可生效。`version.json` 保留为历史文件，页面版本信息以 `data.json` 为准。

## 部署

```bash
npm ci
npm run build
npm start
```

服务默认在 `http://127.0.0.1:3001` 同时提供前端、公司数据、登录和同步 API。仅开发时需要 Vite；`npm run preview` 只预览前端，仍需单独运行后端。

局域网多设备访问可设置 `.env` 中 `HOST=0.0.0.0` 后启动，使用这台机器的局域网 IP 和端口访问。公网部署建议由 HTTPS 反向代理转发到此 Node 服务，并保留外部 `Host`（含端口），例如 Nginx：

```nginx
location / {
    proxy_pass http://127.0.0.1:3001;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

SQLite 文件必须放在持久磁盘上，重启或重新部署时保留；多台设备应连接同一个服务实例。容器部署时将 `DATABASE_PATH` 所在目录挂载为持久卷。数据库使用 WAL，备份时停服后复制数据库目录，或使用 SQLite 在线备份工具，避免运行时只复制主文件而遗漏尚未合并的变更。

服务器在 HTTPS 请求或 `X-Forwarded-Proto: https` 下为登录 Cookie 设置 `Secure`；反向代理应传递正确的协议。登录会话保存在 SQLite 中，只存会话令牌的哈希和有效期。

**GitHub Pages 不能运行 SQLite 后端**；完整功能需要运行上述 Node 服务。同步接口为同源接口，不支持把前端和后端直接部署到不同域名。

## 项目结构与验证

```text
src/App.vue                    主页面、筛选与导入导出
src/components/                公司表格、同步面板、面试助手入口
src/composables/useCompanies.js 动态公司数据
src/composables/useProgress.js  进度迁移、离线队列与同步
src/legacy/                    面试助手模块，首次打开时懒加载
server/                        SQLite、API、生产服务与集成测试
tests/                         同步状态与迁移测试
e2e/                           登录、双设备同步与动态数据浏览器测试
data.json                      公司信息唯一数据源
```

```bash
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

浏览器测试使用独立临时数据库和公司数据，不修改真实进度。已有 Chromium 时可用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定可执行文件。AI 面试助手保留原有离线题库、语音、简历解析及可选大模型功能；其内部模块保持独立，主表格与同步界面使用 Vue 3。
